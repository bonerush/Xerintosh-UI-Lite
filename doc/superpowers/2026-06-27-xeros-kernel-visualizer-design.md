# Xeros Kernel Visualizer 设计文档

> **Parent:** [Superpowers Design Index](index.md)  
> **Related:** [Xeros Kernel Architecture](../../architecture/overview.md), [Xeros Technical Index](../../../index.md)  
> **Status:** 待实现

## 1. 项目定位

构建一个**零构建依赖**的静态网页，通过**逐步动画**可视化 Xeros 自研微内核的关键流程。服务三个目标：

1. **辅助个人理解内核代码**：通过分步动画把抽象的内核机制具象化。
2. **教学演示**：可直接在课堂或文档中打开，讲解启动、调度、同步、SMP 等机制。
3. **调试辅助**：用图形化方式回放流程，帮助定位逻辑问题（数据静态，不连接真实硬件）。

---

## 2. 设计目标

- 打开网页即可运行，无需 npm / PlatformIO / Python。
- 覆盖 Xeros 内核 10 个核心流程。
- 每个流程以**步骤动画**方式播放，支持手动/自动播放。
- 每一步附带：中文说明、源码位置、寄存器/数据结构变化。
- 源码引用直接指向项目文件路径与行号。

---

## 3. 覆盖的内核流程

| 编号 | 模块 | 主要内容 |
|------|------|----------|
| 01 | 系统启动流程 | boot → 硬件初始化 → 内核子系统初始化 → 创建 init 任务 → 启动调度器 |
| 02 | 任务上下文切换 | 保存当前任务寄存器 → 切换栈 → 选择下一个任务 → 恢复寄存器 → 返回用户态 |
| 03 | 调度器流程 | tick 中断 → 更新时间片 → 优先级桶遍历 → 选择最高优先级就绪任务 |
| 04 | SMP 双核调度与 IPI | CPU0/CPU1 独立调度 → 任务迁移 → IPI 跨核唤醒 |
| 05 | 同步原语流程 | spinlock → mutex（含 PI） → semaphore → event group |
| 06 | VFS 调用流程 | open/read/write/close 路径 → inode 查找 → 设备文件分发 |
| 07 | 中断与异常处理 | 中断入口 → 保存上下文 → 分发 ISR → 调度检查 → 恢复返回 |
| 08 | 内存分配流程 | kmalloc 分配 → 空闲块查找 → 分割/合并 → kfree 释放 |
| 09 | 寄存器配置流程 | ESP32 特殊寄存器、CPENABLE、看门狗、定时器、GPIO 配置 |
| 10 | Shell 执行流程 | 串口输入 → 命令解析 → 查找命令表 → 执行回调 → 输出结果 |

## 4. 页面结构

### 4.1 整体布局

```
┌─────────────────────────────────────────────────────────────┐
│  Xeros Kernel Visualizer          [自动播放] [暂停] [重置]     │
├──────────┬───────────────────────────────────────┬──────────┤
│          │                                       │          │
│  模块    │         SVG 动画舞台                   │ 寄存器   │
│  导航    │         （节点高亮 / 箭头流动）         │ 面板     │
│          │                                       │          │
│          ├───────────────────────────────────────┤          │
│          │         步骤详情面板                   │          │
│          │         （说明 / 源码链接 / 变化）      │          │
│          │                                       │          │
├──────────┴───────────────────────────────────────┴──────────┤
│  ◀ 上一步          步骤进度条           下一步 ▶             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 区域说明

- **顶部标题栏**：显示当前模块名称，提供播放控制按钮。
- **左侧导航栏**：10 个模块列表，点击切换场景。
- **中间主舞台**：
  - 上半部分为 SVG 流程图，节点和箭头按步骤高亮。
  - 下半部分为步骤详情，展示中文说明、源码链接、数据结构变化。
- **右侧寄存器面板**：固定展示 ESP32 寄存器表，当前步骤变化的寄存器高亮显示。
- **底部控制栏**：上一步/下一步按钮、步骤进度条、播放速度选择。

## 5. 动画机制

### 5.1 场景驱动模型

每个模块对应一个**场景（scene）**，由 JSON 描述，JS 统一渲染。

```js
{
  id: "context-switch",
  title: "上下文切换",
  steps: [
    {
      id: "save-a0-a15",
      label: "保存通用寄存器 A0-A15",
      highlight: ["cpu-a0-a15", "current-tcb"],
      arrows: ["user-task->cpu"],
      detail: "调用 save_context，把当前任务寄存器压入自己的内核栈。",
      source: "src/kernel/esp32/kern_esp32_context.S:42-58",
      registerChange: { a0: "task_sp+0", a1: "task_sp+4" }
    }
  ]
}
```

### 5.2 渲染方式

- SVG 中预先绘制所有节点和箭头，默认处于灰显状态。
- 每进入一步，通过 `data-step` 激活对应节点和箭头。
- 节点高亮使用 CSS 类切换。
- 箭头流动使用 CSS `stroke-dashoffset` 动画。
- 自动播放按步骤间 `delay` 推进。
- 支持键盘快捷键：空格播放/暂停，左右方向键切换步骤。

### 5.3 视觉风格：暗夜实验室

融合「深色专注感」与「极简结构」的方向 C。设计特征：

- **背景**：深炭黑 `#121214`，适合长时间学习和投影教学。
- **主文字**：柔和的米白 `#fafaf9` / 灰白 `#e8e6e1`。
- **辅助文字**：中灰 `#a1a1aa`、暗灰 `#71717a`。
- **边框/分隔**：深灰 `#27272a`。
- **强调色**：几乎单色调，仅用 `#fafaf9` 作为强对比高亮色，保持克制。
- **结构**：三栏布局、圆角 10px、大量留白，类似精密实验手册。
- **光效**：无发光效果，仅通过明度层级区分状态，更沉静、不疲劳。
- **字体**：无衬线系统字体用于 UI，等宽字体用于寄存器与源码路径。
- **动画**：简洁、技术感，避免花哨过渡；节点状态为未激活（灰）、当前（高亮）、已完成（柔和高亮）。

## 6. 数据来源

完全静态，基于源码提炼：

- 从 `src/kernel/` 各子系统源码中提取真实函数名、文件路径、行号。
- 寄存器配置基于 ESP32 TRM 和代码中已有的寄存器宏。
- 数据结构变化（如 TCB、优先级桶、VFS inode）用简化示意图表示。
- 不依赖运行时数据，也不连接串口或模拟器。

## 8. 技术约束

- **不使用构建工具**：纯 HTML/CSS/JS，浏览器直接打开 `index.html` 即可运行。
- **不使用外部 CDN**：所有依赖（包括可选的图标、字体）尽量内联或随仓库携带，保证离线可用。
- **ESP32/Xtensa 专用**：寄存器名称、ABI、特殊寄存器以 ESP32 为准。
- **中文为主**：所有说明文字、注释、标题使用中文；代码标识符、文件路径保持原文。
