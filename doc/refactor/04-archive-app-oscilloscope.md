## 核心修复（7 P0 → 0 P0）

### 波形可见性（D1）
**问题**：任意非默认时基下波形完全消失
**根因**：环形缓冲 + trigger_index 跨帧搜索 → trigger_index ≥ sample_count → draw_wave 0 点
**修复**：取消环形缓冲，改为线性帧采集；触发搜索限定在 sample_count 内；显示窗口 = remaining

### AC 耦合数据损坏（D2）
**问题**：AC 耦合下半周期被截断为 0（半波整流），Vpp 测量偏小 ~50%
**根因**：去直流后负值 clamp 到 0
**修复**：去直流后 +2048 重新居中

### 频率测量不可靠（D5）
**问题**：无滞回的过零法对噪声敏感
**修复**：增加 Vpp 5% 滞回带，带状态机穿越计数

## 经验教训
1. **环形缓冲区是早期过度设计**：2000 元素环缓冲对 80px 屏幕过量 25 倍，增加了触发/显示映射的复杂性而没有实际的预触发收益。线性帧采集更简单且完全满足需求。
2. **AC 耦合的重新居中**：直接用 clamp(0, v, 4095) 看似自然是错的——它应该 clamp(0, v+2048, 4095) 以保留信号的负向分量。
3. **输入映射一致性很重要**：即使内部自洽（A=减/B=增），与框架全局约定（A=增/B=减）不一致会导致跨 App 的学习成本。
4. **在获取真实硬件反馈前，不要过早"优化"**：轮廓线层叠（D10）和网格密度（D11）保留不改为宜，因为它们都源于之前用户的反馈。
