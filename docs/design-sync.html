第 3 部分：同步原语 (kern_sync)

Spinlock · Mutex · Semaphore — 裸机实现，零 FreeRTOS 依赖

Spinlock

/* 不可抢占的自旋锁 */ typedef struct { volatile uint32_t lock; } spinlock_t; void spin_lock(spinlock_t *s) { while (__sync_lock_test_and_set(&s->lock, 1)) while (s->lock) {} // 读时不自旋，减总线压力 __sync_synchronize(); // 内存屏障 } void spin_unlock(spinlock_t *s) { __sync_synchronize(); __sync_lock_release(&s->lock); }
  • 内核内部保护小临界区（< 10μs）
  • 持有 spinlock 期间禁止抢占（need_resched 被延迟）
  • 单核模式退化为空操作

Mutex (递归锁)

typedef struct { spinlock_t guard; kern_task_t *owner; uint8_t recurse; kern_task_t *waiters; uint8_t orig_prio; // 优先级继承 } mutex_t; /* acquire 流程: */ if (owner == NULL): 获取锁，设为 owner，记录 orig_prio elif (owner == current): recurse++ // 递归获取 else: task→BLOCKED，加入 waiters 链表 // 优先级继承：如果 current.prio < owner.prio owner.prio = min(owner.orig_prio, current.prio) kern_yield()
  • 支持递归获取（同一任务可多次 lock）
  • 优先级继承防反转
  • BLOCKED 等待者让出 CPU，不忙等

Semaphore

typedef struct { spinlock_t guard; int32_t count; uint32_t max_count; kern_task_t *waiters; } sem_t; /* wait 流程: */ if (sem->count > 0): sem->count--; return OK; else: task→BLOCKED，加入 waiters kern_yield() // 被唤醒后重试 /* post 流程: */ if (waiters 非空): 唤醒首个 waiter → READY，入 runqueue elif (count < max): count++
  • 计数信号量，有最大上限
  • Waiting 任务真正阻塞（让出 CPU）

Condition Variable

typedef struct { spinlock_t guard; kern_task_t *waiters; } cond_t; /* 用法（配合 mutex）: */ mutex_lock(m); while (!condition) cond_wait(cv, m); // 原子 unlock+wait // ... 条件满足 ... mutex_unlock(m); cond_signal(cv): 唤醒 1 个 waiter cond_broadcast(cv): 唤醒所有 waiter
  • 与 mutex 配合使用
  • cond_wait 原子释放 mutex 并进入等待
  • 被唤醒后自动重新获取 mutex

与现有同步原语对比

现有实现：kern_sync.c 中的 spinlock/mutex 已经是不依赖 FreeRTOS 的独立实现（使用 __sync_lock_test_and_set）。但 mutex 的 wait_queue 和 BLOCKED 睡眠依赖 kern_yield() → kern_port_task_yield() → 最终走到 FreeRTOS 的信号量协议。

新实现：mutex/sem 的等待者直接调用 kern_yield() → kern_ctx_switch() → 调度器循环，不再经过 FreeRTOS。等待任务被唤醒时由调度器将其从 BLOCKED 移入就绪队列。
