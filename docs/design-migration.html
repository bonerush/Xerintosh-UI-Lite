kern_sleep — 任务睡眠

/* kern_sleep.c — 替代 vTaskDelay */ /* 按唤醒时间排序的睡眠链表（per-CPU）*/ static kern_task_t *g_sleep_list = NULL; void kern_sleep_ms(uint32_t ms) { kern_task_t *task = g_per_cpu[KERN_THIS_CPU].current_task; if (task == NULL) return; task->state = KERN_TASK_SLEEPING; task->wake_tick = g_per_cpu[KERN_THIS_CPU].sched_ticks + ms; // 按 wake_tick 排序插入睡眠链表 // ... 排序插入逻辑 ... kern_yield(); // 让出 CPU → kern_ctx_switch 回调度循环 } /* 每 tick 由调度循环调用 */ void kern_sleep_tick(uint8_t cpu) { uint64_t now = g_per_cpu[cpu].sched_ticks; while (g_sleep_list != NULL && g_sleep_list->wake_tick <= now) { kern_task_t *t = g_sleep_list; g_sleep_list = t->sleep_next; t->state = KERN_TASK_READY; kern_runq_enqueue(&g_per_cpu[cpu].runq, t); } }
调用 kern_sleep_ms(100): 任务 A (RUNNING) ├── state = SLEEPING ├── wake_tick = now + 100 ├── 插入 g_sleep_list ├── kern_yield() └── kern_ctx_switch → 调度循环 ... 100 ticks 后 ... 调度循环 → kern_sleep_tick() ├── 检查 g_sleep_list 头部 wake_tick <= now ✓ ├── 出队 → state = READY ├── kern_runq_enqueue(A) └── 下次 pick_next 选到 A → 恢复执行

注意：ESP-IDF WiFi 栈的边界问题
ESP-IDF 的 WiFi/BLE 协议栈内部大量使用 FreeRTOS 任务和队列。由于你选择了"仅替换内核"，WiFi 等功能需要特殊处理：

短期方案：为新内核实现 FreeRTOS 兼容层（freertos_shim），提供 FreeRTOS API 的桩实现（xTaskCreate → kern_spawn, vTaskDelay → kern_sleep_ms, xQueue → kern semaphore 等），ESP-IDF 组件通过此 shim 运行。
长期方案：逐步替换 ESP-IDF WiFi 栈为裸机驱动，或放弃 WiFi 功能。
